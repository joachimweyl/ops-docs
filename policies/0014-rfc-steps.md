# RFC Creation Steps

Introduction paragraph -- why are we doing anything?

## Problem Description

RFCs are complex and require a specific set of steps to properly create, review, sign-off, and create GitHub issues for.

## Policy

### Step 1: Create RFC From Template
Copy [RFC Template](https://docs.google.com/document/d/1Z8JCf9M4XRTPA6Rgs5joiTpn_90MLSsFAp5lDbUobbY/edit?tab=t.0#heading=h.k3oencsnt9c9) and fill it out as completely as possible

### Step 2: Add RFC To Index Table
Add RFC to [Master index table](https://docs.google.com/document/d/1lbc_mQOa_vLUaDP1ABY-jTVsgwA3sY3efsN4kXXM2Ls/edit?tab=t.g35d7c6yrd40).

### Step 3: Communicate RFC Creation
Announce on Slack/Email about the RFC and due date.
Schedule a time to discuss in real-time, either in a separate meeting or as part of a standing meeting.

### Step 4: Close out
Document the final decision, update status, create any necessary issues or epics identified in the RFC, and move to [Prior RFC folder](https://drive.google.com/drive/folders/1o1MaX89_R65StlyNwfyTykfDqqeK8PPg).

### Step 5: Review the RFC
Read through your approved RFC and identify all action items, open questions, and “closed no action” items — including side comments and feedback section notes.

### Step 6: Update the Creation & Sign-Off Issue
In the MOC 2.0 RFC Creation and Sign-Off epic, find the issue for your specific RFC and add a description listing all action items, open questions, and no-action items.

### Step 7: Populate the Tracking Epic
The tracking epic for your RFC already exists (pre-created up to RFC #12).  Create sub-issues under it for every item that requires doing (action items and open questions).

Items that only need documenting stay in the sign-off issue only — they do not become sub-issues.

### Step 8: Close the Sign-Off Issue
Once the tracking epic is set up and all sub-issues are created, close the sign-off issue to confirm documentation is complete.
Step 5: Continue Work in the Tracking Epic
The tracking epic remains open; it closes only when all its sub-issues are resolved.
